## 2. Update-set capture of a UI-built flow (settles the P4 gate and the D1 payload)

* One `sys_update_xml` row per flow: `name = sys_hub_flow_<flow sys_id>`, **`type = "Flow"`**, `table` **empty**, `target_name = <flow name>`, `action = INSERT_OR_UPDATE`, `category = customer`, `application = global`, `update_domain = global`, `replace_on_upgrade = false`, `update_guid`/`payload_hash`/`sys_recorded_at` populated (`flows/leaver-flow/sys_update_xml_meta.json`).
* **Zero** `sys_update_xml` rows named `sys_hub_action_instance_v2_*`, `sys_hub_flow_logic_instance_v2_*` or `sys_hub_trigger_instance_v2_*` exist on the whole instance: children are captured **through the parent** row. The capture gate must accept one `sys_hub_flow_<id>` row whose payload contains every planned child (the "N rows" form has never been observed here).
* Payload (`flows/leaver-flow/sys_update_xml_payload.xml`, 65 757 bytes): `<record_update sys_domain="global" table="sys_hub_flow">` containing, in this order: `sys_hub_flow` (INSERT_OR_UPDATE), then for each child table a `delete_multiple` element followed by its INSERT_OR_UPDATE rows: `sys_hub_flow_stage` (`flow=<id>^sys_idNOT IN…`), `sys_flow_cat_variable_model` (`id=<id>^sys_idNOT IN…`, catalog flows only), `sys_hub_flow_input` (`model=<id>^sys_idNOT IN…`), `sys_hub_trigger_instance_v2`, `sys_hub_action_instance_v2`, `sys_hub_sub_flow_instance_v2`, `sys_hub_flow_logic_instance_v2` (all `flow=<id>^sys_idNOT IN…`), `sys_documentation` (one per flow input/variable, no delete_multiple). 27 `delete_multiple` elements in total across the file; **`apply_defaults` occurs 0 times**. Reference fields carry `display_value="…"` attributes; fields are emitted alphabetically; `calculation`/`label_cache`/`values` are CDATA or plain text as ServiceNow escapes them.
* Field lists per table as captured are in `flows/leaver-flow/sys_update_xml_payload.xml`; the `sys_hub_flow` row carries 52 fields including `sys_update_name`, `sys_class_name`, `sys_package`, `version_record`, `compiler_build`, `remote_trigger_id`, `copied_from`, `copied_from_name`, `attributes`.

## 4. `sys_hub_flow` row (UI-built) versus the generator's 20 fields

UI-built rows carry (beyond the generator's access, active, allow_high_security_roles, annotation, category, description, flow_priority, generation_source, label_cache, name, run_as, run_with_roles, show_draft_actions, status, sys_policy, type, version, sys_scope): `internal_name`, `sys_class_name = sys_hub_flow`, `sys_package`, `sys_domain`/`sys_domain_path`, `authored_on_release_version`, `compiler_build`, `copied_from`/`copied_from_name`, `attributes` (comma list `browserActivatedIn=chrome,integrationActivatedIn=standalone,viewActivatedIn=naturalLanguage`; OOB rows also `labelCacheCleanUpExecuted=true,timeFromCreateToActivate=…`), `version_record` (a `sys_hub_flow_version` sys_id — the platform creates it), `remote_trigger_id` (published record-trigger flows only), `latest_snapshot`/`master_snapshot`/`master_snapshot_digest` (published only), `pre_compiled`, `sc_callable`, `callable_by_client_api`, `show_triggered_flows`, `natlang`, `outputs`, `substatus`, `updation_source`, `display_name_after_preview`, `acls`. `flow_priority` and `sys_policy` are **empty** on user flows (`MEDIUM` / `read` on OOB rows). `access = public`, `run_as` `user` (default) or `system`, `generation_source` `""` for the UI, `text2flow` for Now Assist-generated flows, `agentic_ai` for AI-agent flows (`catalogue/`). Draft flows have `active=false`, `status=draft`, empty snapshots.

`internal_name` is user-editable and derived on create: lowercase, spaces → `_`, ` - ` → `__` (`Change - Normal - Implement` → `change__normal__implement`, `Certificate task - Record producer customisation` → `certificate_task__record_producer_customisation`), punctuation such as `,`, `/`, `(`, `)`, `:` mostly kept (`new_attachment_on_record_creates_folder,_and_copies_attachment`, `create_task_(legacy)`), in-word hyphens inconsistently kept (`tcm_slack_lookup_user_by_e-mail`) or dropped (`On-Call: …` → `oncall_send_notification__email`), and a numeric suffix is appended on collision (`csm_cases897`, `test_flow030`). The writer should **supply** `internal_name` explicitly (lowercase snake, unique) rather than emulate the derivation.

* **Template reference (settled)**: UI stores references inside `template_value` as JSON: `assignment_group={"display":"Procurement","value":"8a4cb6d4c61122780043b1642efcd52b"}^description=…` (`flows/leaver-flow`, Create Catalog Task `ah_fields`). * **Approval rules**: `ApprovesAllU[{{a}}]G[{{b}}]OrRejectsAnyU[{{a}}]G[{{b}}]`, multiple approvers comma-separated inside a bracket (`U[{{x}},{{y}}]`), rule sets joined by `Or`; a scripted condition stores just `ApprovesAny` with `scriptActive:true`. `due_date` default: `{"action":"none","date_type":"actual","date":"{{}}","duration":1,"duration_type":"days","schedule":"","schedule_label":""}` (note `date` = `"{{}}"`, numeric `duration`).
* **Slushbucket** (`catalog_variables`): comma list of `<item_option_new sys_id>:item_option_new`, variable sets as `<sys_id>:item_option_new_set`.
* **glide_duration**: `1970-01-01 HH:MM:SS` (days in the date part); **glide_time**: `1970-01-01 HH:MM:SS`; **boolean**: `"1"`/`"0"` (display `true`/`false`); **glide_list**: empty string with `valueSysId:""` on the descriptor (no populated example found).
* **Conditions**: raw encoded query (`state=0`, `type=received`), no wrapper.

## 9. Flow Error Handler (settled)

Stored as two extra logic rows plus the handler steps, all in `sys_hub_flow_logic_instance_v2` / `sys_hub_action_instance_v2` (no dedicated table, nothing on `sys_hub_flow`):

* `TOP_LEVEL_TRY` (`e9060aa2c3013010ace8b740ad40dd51`) at `order 0`, `parent_ui_id ""`, empty values; **the whole flow body is nested under it** (body rows have `parent_ui_id` = the try's `ui_id`, orders 1…n).
* `TOP_LEVEL_CATCH` (`35d60003e6022010a5e40cdd1254dd23`) at `order n+1`, `parent_ui_id ""`, values `inputs = [ {name:"__status__", value:<FDACTIONSTATUS complex-object JSON with empty code/message>, children:[{name:"code",parameter{type:integer}},{name:"message",parameter{type:string}}], parameter{id:"0f72a5a25b132010b61ea2013781c749", type:"object"}}, {name:"enabled", value:"1", parameter{id:"dd70187cc36e20105553b740ad40dddc", type:"boolean"}} ]` (verbatim in `flows/error-handler-subflow-snapshot/`).
* Handler steps follow with `parent_ui_id` = the catch's `ui_id` and orders n+2…; they reference the error via `{{<catch ui_id>.__status__.message}}` and the label_cache entry `1 - Error Handler➛Error Status➛Message`.
* Flows without an error handler (Leaver flow) have **no** TOP_LEVEL rows at all — the pair is optional.

## 10. Other constructs

* **Do in parallel**: `PARALLEL` row (top level, empty values) → N `PARALLELBLOCK` rows (`parent_ui_id` = parallel `ui_id`, plain orders 2 and 7) → branch children with `parent_ui_id` = block `ui_id`; the **first** child of a branch carries the `"<block order>➛<child order>"` composite (`2➛3`, `7➛8`), later children plain (`4`, `5`, `9`), and each branch ends with an `End` row. The label_cache label for a branch child is `2➛3➛State`.
* **Exit Loop / Skip Iteration**: empty values, nested under the loop (`parent_ui_id` set).
* **Append to Flow Variables**: no instance rows exist on the PDI (definition present) — shape unverified.
* **Try / Catch (non top-level)**: rows exist (e.g. flows `8c7b6020ff793210c6a9fffffffffff0`, `fd596cecff753210c6a9ffffffffffcf`, `2577994587aa0f18004fc845dabb35eb`) but their values were not decoded in this pass — open.
* **Inline scripts** on a v2 action input: no `sys_hub_input_scripts` row with `referenced_table` = `sys_hub_action_instance_v2` was found (rows reference `sys_hub_action_instance`, `sys_hub_step_instance`, `sys_hub_action_output`); the `values` entry itself carries `scriptActive:true` + `script` for scripted inputs (Set Flow Variables, Ask For Approval). How a v2 flow-level inline script is linked stays open.
* **Record trigger runtime**: publishing a record-trigger flow creates a `sys_flow_record_trigger` row (`table`, `condition`, `on_insert`, `on_update`, `on_delete`, `run_flow_in`, `run_when_setting`, `run_when_user_setting`, `run_when_user_list`, `run_on_extended`, `active`, `sys_scope`, no `flow` column) and stores its sys_id in `sys_hub_flow.remote_trigger_id`. Verify should read it back; a de-activated flow can leave the row `active=true` (`flows/record-trigger-published-flow/`).
